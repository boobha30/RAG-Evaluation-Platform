# Hybrid Retrieval: Combining Dense and Keyword Search

Dense retrieval finds semantically similar text but can miss exact keyword matches, especially for rare terms, product names, error codes, or acronyms that a language model's embedding space does not represent distinctly. Keyword search methods like BM25 solve exactly this problem: they score documents by term frequency and inverse document frequency, rewarding documents that contain the query's exact words, especially rare ones. BM25's weakness is the mirror image of dense retrieval's: it cannot match a query and a passage that express the same idea with different words.

Hybrid retrieval runs both a dense search and a BM25 keyword search over the same corpus and merges the two ranked lists into one. A common and simple merging technique is Reciprocal Rank Fusion (RRF). For each result, RRF computes a score of 1 divided by (a constant k, often 60, plus the result's rank in that particular list), then sums this score across every list the result appeared in. Results that rank highly in both dense and keyword search end up with the highest fused score, while results that only appear in one list still get credit, just less of it. RRF requires no score normalization between the two retrieval methods, which is one of its main advantages over naive weighted-score blending, since dense cosine scores and BM25 scores live on completely different numeric scales.

After fusion, a cross-encoder reranker is often applied to the top candidates. Unlike a dense embedding model, which encodes the query and each passage independently (a "bi-encoder"), a cross-encoder takes the query and a candidate passage together as a single input and outputs a relevance score directly. This lets it model fine-grained interactions between query and passage words that bi-encoders miss, at the cost of being far more expensive to run, since it cannot be precomputed and must score every query-passage pair at request time. Because of this cost, cross-encoders are used only to rerank a small shortlist (typically the top 10-50 candidates from the fused results), not to search the whole corpus.

Adding hybrid retrieval and reranking on top of pure dense search is one of the most reliable ways to improve both retrieval precision and downstream answer faithfulness in a RAG system, because the generator is far more likely to produce a grounded answer when the retrieved context genuinely contains the relevant information.
